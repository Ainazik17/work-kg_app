# Work KG — фронтенд Telegram Mini App

Задача: сверстать фронтенд Work KG точь-в-точь по дизайну из этой папки.

## Источники правды (по приоритету)

1. `screenshots/*.png`: как должен выглядеть каждый экран (390×844 @2x). Результат сверяй с ними визуально.
2. `DESIGN_SPEC.md`: экраны, компоненты, состояния, тексты, поведение.
3. `tokens.css`: все цвета, шрифт, тени, радиусы. Значения не хардкодить, только `var(--…)`.
4. `reference/prototype.html`: рабочий прототип на ванильном JS. Открой в браузере, чтобы посмотреть поведение. Точные CSS-значения любого элемента бери оттуда. Код прототипа не копировать как архитектуру, это демо.
5. `reference/styleguide.html`: все компоненты на одной странице с параметрами.
6. `src-types.ts`: типы данных и мок-данные для экранов.

## Правила

- Ширина макета 390 px, мобильный first. Боковые отступы экрана 20 px.
- Шрифт Onest (Google Fonts, 400/500/600/700/800). Капс нигде не используется.
- Все тексты на русском, брать из `DESIGN_SPEC.md` и скриншотов как есть.
- Иконки: Lucide (`lucide-react` или аналог), stroke 1.8, размеры 22 / 20 / 18.
- Telegram WebApp SDK: `BackButton` на внутренних экранах, `safeAreaInset` / `contentSafeAreaInset` для отступов, `openLink` / `openTelegramLink` для WhatsApp и Telegram, `HapticFeedback` на нажатия по звёздам и главным кнопкам.
- Красный (`--brand`) только для главного действия на экране и ошибок.
- Пока нет API, работай на моках из `src-types.ts` через слой `api/` (одна функция на запрос), чтобы потом заменить на реальные вызовы.

## Стек (если в репозитории ещё нет своего)

React 18 + TypeScript + Vite, роутинг на `react-router` (memory/hash router), стили через CSS Modules + `tokens.css`, `@telegram-apps/sdk-react`.

## Порядок работы

1. Токены, шрифт, базовые компоненты (раздел «Компоненты» в DESIGN_SPEC.md) и страница-витрина компонентов.
2. Таб-бар и роутинг.
3. Экраны по порядку разделов в DESIGN_SPEC.md.
4. После каждого экрана: скриншот 390×844, сравнить с `screenshots/`, поправить расхождения.
